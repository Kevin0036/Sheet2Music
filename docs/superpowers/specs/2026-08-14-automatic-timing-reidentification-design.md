# 越界小节自动定位与二次识别设计

**日期：** 2026-08-14  
**状态：** 已确认，待制定实施计划

## 1. 背景

当前审核机制能识别音符结束位置超出小节边界的问题，但无法自动定位对应图像区域。没有确定性 XML 修复证据时，每个疑点只能要求用户单独上传放大图。

Nautilus 任务 `8f7ec48483fd` 共发现 27 个 `timing_measure_overflow`。逐项检查表明，大部分音符的 `<duration>` 与音符类型、附点和连音标记一致；越界主要来自 HOMR 在小节线之间识别出了过多的音符或空隙。它不是左右手换音区造成的小节长度变化，也不能通过统一缩放时值可靠修复。

本次迭代在现有固定边界分析之上增加自动版面定位、谱表区域批量二次识别和候选验证。用户上传只作为所有自动方案失败后的最终手段。

## 2. 目标

- 首次识别时保存“页码、谱表系统、小节范围、图像坐标”的可靠映射。
- 将同一谱表系统中的多个疑点合并为一个自动处理批次。
- 从已有 600 DPI 页面自动裁出完整谱表系统并生成多个识别候选。
- 只在候选满足固定边界、版面证据和全谱回归验证时自动采用。
- 自动替换不能在目标范围外新增高风险疑点。
- 候选冲突时只让用户审核冲突区域；没有合法候选时才要求上传。
- 所有裁图、候选、决策和验证结果可以审计、恢复和回退。

## 3. 非目标

- 不实现通用五线谱手工编辑器。
- 不通过统一比例压缩整小节掩盖多识别或漏识别。
- 不根据“修改量最小”直接选择候选。
- 不自动猜测缺失的拍号、谱号或调号变化。
- 不因二次识别而替换目标范围之外的正常小节。
- 不保证所有越界小节都能无人介入修复；无法形成可靠候选时必须降级到人工处理。

## 4. 核心决策

### 4.1 以谱表系统为重识别区域

自动二次识别的最小图像区域是完整谱表系统，而不是单个小节。区域包含：

- 同一系统内的上、下谱表；
- 行首谱号、调号和拍号；
- 系统左右边界及安全边距；
- 目标疑点小节及同一系统中的相邻小节。

这样可以保留 HOMR 需要的结构上下文。同一系统内的多个疑点只裁图和推理一次。

### 4.2 只替换目标小节

系统级候选用于定位和一致性验证，但正式写回时只替换该批次中原本存在高风险疑点的小节。相邻正常小节仅作为锚点，不随候选变化。

### 4.3 高置信候选允许自动采用

当候选唯一、通过全部硬性条件并满足一致性规则时，系统可以直接采用，不要求用户逐项确认。自动采用必须记录候选来源和验证依据。

### 4.4 自动替换必须是事务

每个谱表系统独立处理。候选先写入临时 MusicXML 并重新分析整谱；只有全部验证通过后才写入正式候选。任何验证失败都撤销该系统的全部自动修改。

## 5. 版面映射

### 5.1 HOMR 布局边车文件

首次 HOMR 识别增加可选的 `layout.json` 输出。它保存页面坐标中的检测结果，不改变 MusicXML 格式。

```json
{
  "schema_version": 1,
  "page": 6,
  "source_image": {"width": 4958, "height": 7016},
  "recognition_image": {"width": 2479, "height": 3508},
  "systems": [
    {
      "system_index": 0,
      "bbox": [120, 180, 2380, 740],
      "staff_bboxes": [[130, 210, 2370, 350], [130, 470, 2370, 620]],
      "barline_x": [150, 980, 1710, 2350],
      "local_measure_start": 1,
      "local_measure_end": 3,
      "mapping_confidence": "high"
    }
  ]
}
```

版面坐标来自 HOMR 已检测到的谱表和小节线。输出同时记录识别图与 600 DPI 原图尺寸，裁图时按明确比例映射回原图。

### 5.2 映射验证

系统映射必须满足：

- 上、下谱表能组成稳定的钢琴大谱表；
- 小节线按横坐标严格递增；
- 系统数量和 MusicXML 的换行结构可以对应；
- 小节数量与页面 MusicXML 可以唯一对齐；
- 坐标位于图像边界内且区域面积合理。

任一条件不满足时，`mapping_confidence` 不得为 `high`，该区域禁止自动替换。系统可以继续尝试整页重识别，但不能用猜测坐标裁切并写回。

### 5.3 音符视觉证据

边车文件还应按小节保存分割模型检测到的音符头数量和横向位置摘要。它作为独立于 Transformer 输出的证据，用于拒绝明显漏音或跨小节错位的候选，不用于直接生成音高。

## 6. 自动处理批次

分析完成后，将 `timing_measure_overflow` 按页面和谱表系统分组：

```text
AutoResolutionBatch
  id
  page_number
  system_index
  target_measure_numbers
  context_measure_range
  source_crop
  status
  attempts
  candidates
  selected_candidate
  validation
```

批次状态为：

```text
pending -> locating -> recognizing -> validating
        -> auto_resolved
        -> needs_choice
        -> needs_upload
        -> failed
```

状态和中间产物持续写入任务目录。服务重启后从最后一个完整阶段继续，不重复已完成的 GPU 推理。

## 7. 候选生成

每个谱表系统最多运行三种确定的图像方案：

1. 600 DPI 原图按标准边距裁切，使用现有 HOMR 预处理。
2. 同一区域进行保守对比度增强后识别。
3. 调整安全边距和输入缩放，保留完整行首结构后识别。

三种方案使用同一模型权重，但输入不同，用于产生独立候选。相同图像和参数不重复运行。GPU 不可用时不静默启动大量 CPU 重试；任务显示降级原因，并按配置决定单次 CPU 尝试或直接进入人工流程。

候选 MusicXML 先规范化，去除排版、生成时间等与音乐内容无关的差异，再计算内容指纹。

## 8. 候选硬性条件

任何一项失败，候选立即淘汰：

- MusicXML 可解析且包含预期的钢琴谱表结构；
- 候选小节数量与版面映射一致；
- 相邻正常小节能与原结果唯一对齐；
- 所有 MusicXML 游标合法，不出现负游标；
- 目标小节的音符结束位置不越过有效拍号边界；
- 目标小节没有新增无法解释的结构诊断；
- 音符坐标按阅读顺序单调，并落在对应小节线之间；
- 候选音符数量与分割模型的独立视觉证据在容差范围内；
- 候选没有未经确认地改变拍号、调号或谱号；
- 候选不会要求修改目标范围外的小节。

声部提前结束仍然合法，不能仅因小节未填满而淘汰候选。BPM 变化不参与小节容量判断。

## 9. 自动选择规则

候选先经过硬性条件，再按以下顺序决定：

1. 两种或以上图像方案得到相同的规范化候选时，视为一致候选。
2. 一致候选通过临时替换和全谱验证后自动采用。
3. 三次尝试中只有一个候选通过硬性条件时，只有在视觉覆盖正常、相邻锚点一致、结构属性未改变且全谱验证通过时才自动采用。
4. 多个合法候选内容不同，状态改为 `needs_choice`，不自动按分数选择。
5. 没有合法候选时，状态改为 `needs_upload`。

自动选择不使用单一、不透明的加权总分。硬性条件、候选一致性和全谱验证分别记录，让采用原因可以向用户解释。

## 10. 事务替换与回归门槛

候选只在临时副本中替换目标小节，然后重新运行现有全谱分析和导出前边界验证。自动采用必须同时满足：

- 当前批次对应的越界疑点减少或全部消失；
- 目标范围内不新增其他高风险时值疑点；
- 全谱任意位置都不新增高风险疑点；
- 原有、与本批次无关的审核决定保持有效；
- 页面和全局小节编号保持不变；
- 最终 MusicXML 通过固定小节边界验证。

验证失败时丢弃临时副本，保留原始候选，并在批次记录中保存失败原因。多个不重叠批次可以依次提交；每次提交都以最新正式候选为基线重新验证。

## 11. 审核界面

### 11.1 自动检查阶段

首次分析发现越界后，界面先显示自动处理进度，而不是立即列出所有上传控件：

```text
发现 27 处小节边界疑点
已合并为 9 个谱表区域
自动解决 6 个 · 需要选择 2 个 · 仍需补充图片 1 个
```

自动解决项默认收起，可展开查看页码、小节范围、原结果、采用结果和采用依据。

### 11.2 候选冲突

`needs_choice` 项显示：

- 页码、小节范围和左右手范围；
- 从原始页面自动裁出的谱表图像；
- 原识别结果及每个候选的中文摘要；
- 每个候选的小节占用拍数、结构变化和验证状态。

用户可以选择一个合法候选、重新运行自动识别或进入最终上传。仍然越界的原结果不能作为可导出的“保留”决定。

### 11.3 最终上传

只有 `needs_upload` 才显示上传入口。页码和小节范围由系统预填，用户一次上传完整谱表系统即可处理其中多个疑点。上传结果走相同的硬性条件和事务验证，不能绕过边界门槛。

### 11.4 提交条件

提交按钮依据批次状态和现有谱号审核共同计算：

- `auto_resolved` 视为已处理；
- `needs_choice`、`needs_upload`、`failed` 仍阻止提交；
- 所有剩余人工项目有有效决定后按钮必须可用；
- 页面刷新后计数和按钮状态必须由持久化数据恢复。

## 12. 谱号审核关系

本次自动流程首先解决 `timing_measure_overflow`。现有小节开头和小节中途谱号审核继续保留。

新版布局映射用于给谱号项显示准确的原图位置。自动二次识别候选如果改变谱号、拍号或调号，不能作为纯时值修复自动采用；该变化必须形成独立结构审核项。只有多个候选一致且后续规则明确支持时，才可在未来迭代中自动处理结构变化。

## 13. 文件与接口

任务目录增加：

```text
layout/page-N.json
auto_resolution/batches.json
auto_resolution/crops/<batch-id>-<variant>.png
auto_resolution/candidates/<batch-id>/<variant>.musicxml
auto_resolution/validation/<batch-id>.json
```

任务状态和报告增加 `auto_resolution` 摘要，但保持现有 `analysis.findings` 兼容。前端通过任务轮询读取批次进度，不要求保持长连接。

旧任务没有 `layout.json` 时，可以从保留的页面图重新运行一次布局检测。若无法建立高置信映射，则按失败降级规则处理，不伪造坐标。

## 14. 错误处理

- 裁图失败：保留任务和映射诊断，批次进入 `needs_upload`。
- HOMR 单次失败：记录错误并尝试下一个尚未运行的图像方案。
- 所有自动尝试失败：进入 `needs_upload`，不影响其他批次。
- GPU provider 丢失：明确显示执行环境变化，不自动触发多轮缓慢 CPU 推理。
- 候选无法对齐：淘汰候选，不按位置猜测小节编号。
- 全谱验证失败：事务回滚，批次进入 `needs_choice` 或 `needs_upload`。
- 服务重启：从持久化批次状态恢复；不重复成功候选，不丢失用户决定。

## 15. 测试

### 15.1 单元测试

- 页面坐标到 600 DPI 原图坐标的缩放。
- 谱表系统、小节线和全局小节号映射。
- 映射歧义时禁止自动替换。
- 同一谱表系统中的多个疑点合并为一个批次。
- 候选规范化和内容指纹。
- 两个一致候选自动采用。
- 唯一合法候选的附加证据门槛。
- 多个合法但冲突的候选进入 `needs_choice`。
- 无合法候选进入 `needs_upload`。
- 事务验证失败后 XML 完整回滚。
- 正常声部提前结束不被误判。

### 15.2 集成测试

- 首次识别生成 MusicXML 和布局边车文件。
- 自动裁图保留完整上下谱表和行首结构。
- 系统级候选只替换目标小节。
- 二次识别不能增加目标范围外疑点。
- 服务重启后恢复批次和候选状态。
- 全部自动项目解决后提交按钮正确启用。
- 最终上传结果也必须通过相同验证。

### 15.3 Nautilus 回归

使用任务 `8f7ec48483fd` 对当前 27 个越界项执行完整流程，记录：

- 合并后的谱表系统数量；
- 自动解决数量；
- 候选冲突数量；
- 最终需要上传的区域数量；
- 自动处理前后的全谱高风险疑点差异。

验收要求自动流程不能增加全谱高风险疑点。对第 72、75、76 小节以及其他发生明显停顿的段落导出 MIDI/MP3 进行边界检查和试听，确认不再因小节扩张产生额外停顿。
