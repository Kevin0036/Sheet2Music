# 小节时值与谱号审核机制迭代设计

**日期：** 2026-08-11
**状态：** 待用户确认后实施

## 1. 目标

重构 Sheet2Music 的预分析、自动修复和人工审批机制，使普通小节始终服从有效拍号规定的边界，同时正确处理附点、连音、和弦、休止、跨谱表演奏以及小节中途谱号变化。

本次迭代必须满足：

- `16`、`96` 等 MusicXML 内部计数先归一化为拍数，再用于分析和展示。
- 左右手换音区、谱号变化和附点不能自行改变小节长度。
- 谱号事件必须精确到谱表、小节和小节内拍位。
- 只有能从记谱证据唯一确定正确时值时，才向用户提供自动压缩。
- 无法确定的时值问题必须通过区域二次识别处理。
- 未解决的小节越界必须阻止 MIDI/MP3 导出。

## 2. 非目标

- 不按比例强制缩放整个小节。
- 不猜测或改写音高。
- 不移动音符到相邻小节。
- 不在本轮实现手工逐音符编辑器。
- 不把 BPM 变化当作小节记谱容量变化。

## 3. 统一术语

### 3.1 小节容量

小节容量由有效拍号决定。例如 `4/4` 的容量是四个四分音符拍，`2/4` 的容量是两个四分音符拍。

### 3.2 内部计数精度

MusicXML `<divisions>` 表示一个四分音符包含多少内部单位。`4/4 + divisions=4` 的容量是 `16` 单位，`4/4 + divisions=24` 的容量是 `96` 单位；二者都等于四拍。

报告内部保留整数单位用于无损运算，API 和界面同时提供归一化字段：

```json
{
  "divisions": 24,
  "occupied_units": 114,
  "expected_units": 96,
  "occupied_beats": "19/4",
  "expected_beats": "4",
  "difference_beats": "3/4"
}
```

拍数使用有理数序列化为字符串，不使用浮点数。

### 3.3 小节内位置

所有结构事件使用以下位置：

```text
measure_number + offset_units/divisions
```

界面将其显示为“第 15 小节开头”或“第 15 小节第 2.5 拍后”。

## 4. 时间轴模型

新增独立的 MusicXML 时间轴模块，按文档顺序解释事件：

- 普通音符在当前游标开始，结束位置为 `onset + duration`。
- 和弦音符与前一个非和弦音符共享起点，不推进游标。
- `<forward>` 推进游标。
- `<backup>` 回退游标；回退到零以下是非法结构。
- grace note 不推进游标。
- 谱表 `staff` 只表示显示位置，不作为时间通道身份。
- `voice` 用于关联声部，但实际起点始终以 MusicXML 游标为准。

每个小节输出：

```python
MeasureTimeline(
    measure_number: int,
    divisions: int,
    expected_units: int,
    final_cursor_units: int,
    maximum_note_end_units: int,
    events: tuple[TimedNote, ...],
    diagnostics: tuple[TimingDiagnostic, ...],
)
```

小节是否越界以 `maximum_note_end_units > expected_units` 为准，不能只看文档末尾游标，也不能要求每个声部都填满整小节。声部提前结束是合法的，其余空间代表休止。

## 5. 记谱证据与确定性修复

对每个带时值的音符，使用以下证据计算记谱期望值：

- `<type>` 基础音符类型；
- `<dot>` 附点数量；
- `<time-modification>` 连音比例；
- `<chord>` 和弦起点；
- `<duration>` HOMR 当前识别值；
- 当前有效 `<divisions>`。

只有以下条件全部满足，才生成“自动压缩”建议：

1. 每个被修改音符都能由 `type + dot + time-modification + divisions` 得到唯一整数时值。
2. 修正后所有音符结束位置不超过小节边界。
3. 修正不改变音高、和弦关系、声部顺序或小节归属。
4. 修正不要求按比例缩放无法解释的音符。
5. 修正后的时间轴通过第二次独立验证。

自动修复可执行：

- 更正与记谱证据冲突的 `<duration>`；
- 删除或重建可证明错误的 `<backup>/<forward>`；
- 在小节尾部补充必要的静默 `<forward>`，但不把它描述成音乐停顿修复。

遇到重复音符、缺失音符、无法解释的连音、缺失 duration 或修正后仍越界时，不生成自动压缩建议，只允许区域二次识别。

## 6. 疑点分类

### 6.1 时值类

- `timing_notation_mismatch`：duration 与音符类型、附点或连音证据冲突；可能有确定性修复。
- `timing_cursor_invalid`：负游标、非法 backup/forward 或无法确定音符起点；必须二次识别。
- `timing_measure_overflow`：音符结束位置超出小节容量；确定性修复存在时可选择自动压缩，否则二次识别。
- `timing_measure_underfill`：整小节音乐提前结束；仅作为诊断信息，除非同时发现疑似漏音证据，否则不阻断。

时值类不再统一使用含糊的 `timing_structure`。

### 6.2 谱号类

- `clef_change_at_measure_start`：偏移量为零的小节开头变化。
- `clef_change_mid_measure`：偏移量大于零的小节中途变化。
- `clef_mismatch`：与用户已确认的谱号事件不一致。

每项必须包含：

```json
{
  "staff": 2,
  "hand_region": "left",
  "measure_start": 15,
  "offset_units": 24,
  "offset_beats": "1",
  "previous_clef": {"sign": "F", "line": 4},
  "observed_clef": {"sign": "G", "line": 2}
}
```

谱号变化仅影响该位置之后音符的音高解释，绝不改变时间轴。

## 7. 审批动作

不同疑点提供不同动作，不再让所有疑点共享同一组三选一按钮。

| 疑点类型 | 可用动作 |
|---|---|
| 拍号变化 | 保留谱面变化、采用修复建议、二次识别 |
| 小节开头谱号变化 | 保留谱面变化、采用修复建议、二次识别 |
| 小节中途谱号变化 | 保留谱面变化、采用修复建议、二次识别 |
| 有确定性修复的时值异常 | 自动压缩、二次识别 |
| 无确定性修复的时值异常 | 二次识别 |

时值异常不提供“保留当前识别结果”。自动压缩按钮必须展示具体变化，例如：

```text
当前占用：4.75 拍
拍号容量：4 拍
建议：根据 2 个附点音符和 1 个连音标记修正为 4 拍
```

二次识别后显示新增、已解决和未变化疑点，并重新要求审批。

## 8. 谱号结构计划

现有按完整小节范围表达的 `ClefOverride` 继续兼容，但新增精确事件：

```python
ClefEvent(
    staff: int,
    measure_number: int,
    offset_units: int,
    divisions: int,
    sign: str,
    line: int,
)
```

`offset_units=0` 表示小节开头。中途事件按其原始 XML 顺序插入，事件有效期持续到同一谱表的下一次谱号事件。旧的完整小节覆盖在读取时转换为开头事件，在写回时保留兼容字段直至迁移完成。

## 9. 最终导出门槛

最终化流程必须在 MuseScore 前执行全谱验证：

- 普通小节不得有负游标。
- 普通小节不得有音符结束位置超过拍号容量。
- 所有待审批高风险疑点必须有可执行决定。
- 自动压缩决定必须已经应用并通过重新分析。
- 二次识别决定必须存在已合并候选 XML。

任一条件失败时返回审核状态，不创建最终 MIDI/MP3。

MuseScore 导出后再验证：

- MIDI 拍号事件与结构计划一致。
- MIDI 总结构边界与 MusicXML 计划一致。
- MIDI 修复不得仅改拍号元数据后掩盖未移动的错误音符时间。

## 10. 用户界面

普通用户界面只显示拍数和可读位置，不显示裸 `cursor=114, expected=96`：

```text
需要审阅的位置：第 15 小节，第 2.5 拍后，左手区域
当前识别结果：低音谱号变为高音谱号
影响范围：从该位置开始，直到下一次谱号变化
```

时值项显示受影响谱表集合：右手、左手或上下谱表均涉及。若无法归属到单一谱表，明确显示“上下谱表均涉及”，不再显示“未提供谱表编号”。

## 11. 失败处理

- 自动压缩应用失败：保留原候选 XML，返回审核并说明失败原因。
- 二次识别失败：保留原候选和上传图像，允许重试。
- 二次识别引入范围外状态变化：恢复区域后的 divisions、拍号、调号和谱号继承状态，再重新分析。
- 最终验证失败：不产生音频文件，列出仍阻断导出的具体小节。

## 12. 测试与验收

### 12.1 最小单元场景

- `4/4 + divisions=4` 的 16 单位与 `4/4 + divisions=24` 的 96 单位都显示为 4 拍。
- 附点八分音符、双附点和三连音得到精确有理数时值。
- 和弦不重复推进游标。
- 同一 voice 在 staff 2 与 staff 1 之间切换时保持连续时间线。
- 小节开头谱号变化偏移为零。
- 小节中途谱号变化保留精确偏移，不影响前序音符。
- 声部提前结束不产生高风险越界。
- 音符超过边界且无确定性修复时只允许二次识别。

### 12.2 工作流场景

- 自动压缩决定实际修改候选 XML，并在重新分析后解决对应疑点。
- 无自动建议的时值项无法提交“保留”或“自动压缩”。
- 未解决越界时不生成 MIDI/MP3。
- 区域二次识别只替换指定范围并报告前后差异。
- 服务重载后审核状态仍可恢复；任务持久化作为工作流验收前置条件。

### 12.3 Nautilus 回归场景

- 第 14-17 小节的左手谱号变化按开头或中途位置准确展示。
- 第 25 小节 `2/4`、第 26 小节恢复 `4/4`，边界分别为 2 拍和 4 拍。
- 第 72、75、76 小节不得将超长 MusicXML 原样导出。
- 全部普通小节通过固定边界验证后才允许生成 MIDI/MP3。
- 对修复前后 MP3 的对应段落进行试听，确认不存在由小节扩张引入的额外停顿。

## 13. 实施顺序

1. 建立当前失败谱例和固定边界回归测试。
2. 新增独立时间轴解析器和拍数归一化模型。
3. 重写时值疑点分类，不改变修复行为。
4. 实现记谱证据校验和确定性自动压缩。
5. 扩展谱号事件模型，支持小节开头和小节中途变化。
6. 根据疑点能力限制审批动作并更新中文界面。
7. 在最终导出前增加硬性边界验证。
8. 对 Nautilus 执行完整识别、审批、二次识别、导出和试听验收。
